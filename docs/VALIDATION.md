# Safety validation report

Validated on **2026-10-12** against the safety changes based on
`11192482a157bb0bd09ebb3363df6378f91c6661` (Farvist 1.8.1).
This repository did not previously contain a tracked validation report.

The changes improve command activation, clipboard feedback, CLI input handling,
development dependencies, and CI permissions. Local validation passed the build
and quality checks listed below. The full development dependency audit still
reports an unresolved upstream advisory; this is not a clean security audit.
No npm release or production deployment is included in this validation.

## Verified changes

| Area | Previous behavior | Validated behavior |
| --- | --- | --- |
| Command palette | An `aria-disabled="true"` item could still become active and dispatch `fv:command`. | Mouse and keyboard activation reject disabled, hidden, and inert items. Navigation skips unavailable actions; a command disabled after selection also stays inactive. Disabled anchors cannot navigate through their default click behavior. |
| Clipboard | The fallback displayed success even when `execCommand('copy')` returned false or threw. | `Farvist.copy()` resolves to a boolean. Only confirmed writes display success; failure displays manual-copy guidance. Temporary fields are removed and focus is restored, including fallback inside a modal. |
| CLI validation | Missing option values were silently accepted or consumed another option; an empty or partially unreadable scan could exit successfully. | Invalid options exit 2. Empty or skipped-input scans exit 2 and report `summary.complete: false`; complete scans retain exit 0/1 for valid/invalid markup. |
| CLI file reads | Markup and explicit CSS reads were unbounded; linked CSS could use Windows drive or network paths. | Markup and CSS reads are restricted to regular files and 5,000,000 bytes each, with the read itself bounded. Implicit CSS discovery accepts relative references only. Explicit `--css` paths remain supported. |
| Text rendering | Toast and streaming messages already used text nodes. | Regression checks confirm HTML-like message content stays literal text and does not create elements or execute handlers. |
| CI | Action tags were mutable, token permissions were implicit, checkout credentials persisted, and Node 20 was below the installed Puppeteer's supported version. | Actions are pinned to verified commit SHAs, permissions are `contents: read`, checkout credentials are not persisted, the job is limited to 20 minutes, and development uses Node 24. Safety regressions and a runtime dependency audit are required. |

UI disabling is not authorization. Applications must authorize their own action
handlers and backend requests. The CLI remains a markup checker, not a sandbox:
it follows local symlinks and relative CSS references, does not impose a total
scan resource budget, and intentionally tolerates absent stylesheets that may be
generated by a bundler. Its `complete` flag refers to this documented scope.

## Dependency audit

The initial lockfile audit reported **18 affected development packages**
(17 high, 1 moderate). After the changes, `npm audit --json` reports **10 high**
entries, all tracing to the same `braces` advisory through the Stylelint toolchain.
These are affected-package counts, not distinct vulnerabilities.

| Package | Before | Validated lockfile |
| --- | --- | --- |
| axios | 1.19.0 | 1.20.0 |
| compression | 1.8.1 | 1.8.2, scoped override for `serve`'s pinned dependency |
| postcss-selector-parser | 7.1.4 | 7.1.6 |
| source-map-js | 1.2.1 | 1.2.2 |
| undici | 6.28.0 | 6.29.0 |
| postcss-cli / chokidar | 11.0.1 / 3.6.0 | 12.0.0 / 5.0.0, removing this path to `braces` |

`npm audit --omit=dev --json` reports **0 vulnerabilities**. Farvist has no
runtime npm dependencies; that result does not certify its browser code or CLI.

Remaining: [GHSA-vfj7-8cjw-p6xm](https://github.com/advisories/GHSA-vfj7-8cjw-p6xm)
affects `braces` through 3.0.3 and has no published patched version as of this
validation. The dependency remains under `micromatch` / `fast-glob` / Stylelint.
The documented lint command uses a fixed repository glob; this does not remove
the advisory or prove every use of those tools safe. Do not expose those tools
as a service accepting untrusted glob patterns. Replace/update that dependency
chain when an upstream fix is available, then rerun the full audit.

CI's audit gate covers runtime dependencies. The full development audit remains
nonzero and must be reviewed separately; it is not suppressed or described as
passing. Deprecation warnings for `glob`, `inflight`, and `whatwg-encoding` also
remain in the development install.

failing tests and one passing text-rendering test (plus one platform skip).

translucent/gradient surfaces; the separate contrast gates above cover the
configured measurements. Passing these checks is not a full WCAG certification.

[Ubuntu AppArmor namespace restriction](https://pptr.dev/troubleshooting#issues-with-apparmor-on-ubuntu)
without adding `--no-sandbox` to the new regression suite. Existing rendering
checks retain their previous browser configuration.

The final documentation update adds this evidence; it does not change the
application, dependency lockfile, test code, or workflow validated by that run.
