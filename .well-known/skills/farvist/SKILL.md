# Farvist

Farvist is a free, MIT-licensed CSS framework: one stylesheet, no build step, dark "frosted glass" look by default. Its class model is Bootstrap-like (components + utilities). It also ships a kit of AI-interface components. Every colour derives from `--fv-*` custom properties at runtime, so a page re-brands by overriding a few variables.

## 1. Set up — pick the build

| Build | Size | Use when |
|---|---|---|
| `farvist.min.css` | ~21.3 KB gzip | Farvist is the page's framework (everything, incl. the AI kit) |
| `farvist-slim.min.css` | ~19.2 KB gzip | Same, but the page renders no AI conversation UI |
| `farvist-ai.min.css` | ~6.6 KB gzip | Adding ONLY the AI kit to a page already styled with Tailwind, Bootstrap or custom CSS |

```html
<link rel="stylesheet" href="https://cdn.jsdelivr.net/npm/farvist@1/dist/farvist.min.css">
<!-- optional: modals, tabs, toasts, theme toggle, command palette, auto-ARIA -->
<script src="https://cdn.jsdelivr.net/npm/farvist@1/assets/farvist.js" defer></script>
```

Or `npm i farvist` and import `farvist/dist/farvist.min.css`.

## 2. Rules — the mistakes agents actually make

1. Load Farvist from a **version-pinned** URL (`farvist@1`), never an unversioned one — `latest` would silently pick up a future major. Pick the build that matches the page (see the table above).
2. Use **only real Farvist classes** — never invent or "guess" a class name. Look it up in the references below, and run `npx farvist check` on the files you generated before you finish.
3. The class model is **Bootstrap-style components + utilities, not Tailwind**: `d-flex` not `flex`, `align-items-center` not `items-center`, `fw-bold` not `font-bold`, `w-100` not `w-full`, `mt-3` (no arbitrary values like `mt-[13px]`), `col-md-6` on a `.row`.
4. Glass needs something to blur: give the page a **rich background** — `<body class="bg-mesh-aurora">` (also `bg-mesh-sunset|ocean|nebula`, `bg-grid`, `bg-dots`). Glass over a flat colour just looks grey.
5. Wrap **rendered LLM markdown** in `.prose` (`.prose.prose-sm` inside a `.message-bubble`) — bubbles preserve raw newlines for plain text, so unwrapped HTML gets stray gaps and hero-sized headings.
6. Theme with `data-theme="light"` or a skin (`cyber|dawn|forest|noir|synthwave`) on `<html>`. **Re-brand** by setting `--fv-primary` / `--fv-accent` / `--fv-info` on `:root` — every gradient, glow and hover state follows at runtime. Never re-colour by overriding component CSS. If a brand colour is light, also set `--fv-primary-contrast` (text on filled buttons).
7. The **icon sprite must be served from the page's own origin**: `<svg class="icon" aria-hidden="true"><use href="/assets/icons/farvist-icons.svg#i-NAME"/></svg>`. Browsers block cross-origin `<use>`, so never point it at a CDN — copy `assets/icons/farvist-icons.svg` into the project.
8. Never convey meaning **by colour alone**: keep the visible status text in `.tool-call-status` and `.status`, keep the `+`/`−` characters inside `.diff-line`s, and give every icon-only button an `aria-label`.
9. Using `farvist-ai.min.css` on a **Tailwind v3 or Bootstrap** page? Also load `farvist-ai-compat.css` after the host stylesheet (their un-layered resets and `.btn` otherwise strip the kit's buttons and borders; Tailwind v4 needs nothing). On a light host page, wrap the kit in `data-theme="light"`.
10. Interactive parts are **data attributes + the optional `farvist.js`**: `data-fv-open="#id"` (modal / command palette), `data-fv-dismiss`, `data-fv-tab="#panel"`, `data-fv-theme-toggle`, `data-fv-nav-toggle`. Call `Farvist.enhance()` after injecting new DOM so ARIA gets wired.

## 4. Verify before you finish

Run the validator on every file you created or changed:

```bash
npx farvist check index.html src/components
```

It reports unknown or misspelled Farvist classes (with a suggestion), classes the page's build doesn't contain (for example an AI-kit class on a page that loads `farvist-slim`), icon sprites loaded cross-origin, and unpinned CDN URLs. `--json` gives machine-readable output; the exit code is 1 when there are errors. Fix every error, then re-run.

It checks class names and a few documented pitfalls only. It does not judge visual design or full accessibility — keep following the rules above for that.
